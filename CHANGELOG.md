# Changelog

Все заметные изменения проекта фиксируются в этом файле.
Формат — Keep a Changelog, семантическое версионирование.

## [3.0] - 2026-11-20

Фаза 3 дорожной карты «Пилот» (недели 23–30): инструменты измерения
KPI пилота, сбор жалоб на наставника, обучение комиссии.

### Fixed
- **MinIO → RustFS в docker-compose.yml**: MinIO удалил свои образы
  из Docker Hub (окт 2025) и закрыл анонимный доступ к зеркалу quay.io
  (401 на все теги) — `docker compose up` падал с «not found». Заменён
  на S3-совместимый RustFS (`rustfs/rustfs:latest`, те же порты 9000/9001,
  Apache 2.0). Критично для развёртывания пилотного стенда. Код
  приложения пока не зависит от S3 (документы в PostgreSQL,
  `fileUrl` — задел фазы 4), обновлены README и architecture.md.
- **`.env` в монорепо**: Prisma CLI ищет `.env` в `packages/database`,
  Next.js — в `apps/web`, а файл лежал только в корне → `db:push` падал
  с P1012 «Environment variable not found: DATABASE_URL». Добавлен
  кросс-платформенный скрипт `env:setup` (`scripts/setup-env.mjs`):
  создаёт корневой `.env` из примера и раскладывает копии по пакетам;
  `db:push`/`db:seed` вызывают его автоматически.
- **Генерация Prisma-клиента**: npm 11.20+ блокирует postinstall-скрипты
  (`@prisma/client`, `@prisma/engines`) → seed падал с «@prisma/client
  did not initialize yet». Добавлен скрипт `db:generate`, в README
  описан явный шаг генерации после `npm install`.
- **Зависание `next dev` на Windows**: Turbopack (компилятор по умолчанию
  в Next 16) молча виснет до старта на части Windows-машин (взаимодействие
  с антивирусами). Dev-скрипт переведён на стабильный webpack
  (`next dev --webpack`); build остался на Turbopack.

### Added
- **Оценка ответов наставника** (`AIMessage.feedback`): сотрудник
  отмечает «Полезно» / «Ответ неточен» под каждым ответом; отметка одна
  и неизменяемая, принадлежность сообщения диалогу сотрудника проверяется
  на сервере (`POST /feedback` в ai-mentor + прокси `/api/ai/feedback`).
  `DOWN` — жалоба на неточность, метрика пилота «≤ 5% диалогов».
- **KPI-отчёты пилота** (`lib/reports.ts` + `/reports`): доля прошедших
  в срок (≥95%), среднее время прохождения (≤30 мин), доля протоколов,
  подписанных за 1 рабочий день (≥90%), обращения к наставнику за 30
  дней (≥3 на сотрудника), жалобы (≤5%); разрез по подразделениям.
- **Экспорт CSV** (`/api/admin/reports/export`): Excel-совместимая
  выгрузка всех KPI против целей и таблицы подразделений — сводка
  по итогам пилота.
- **Памятка члена комиссии** (`docs/pilot-guide.md`): 15-минутное
  обучение перед пилотом — вход, поток протокола, правила подписания
  (решение неизменяемое, цель 1 рабочий день), печатная форма, разбор
  жалоб на наставника, типичные ситуации.

### Changed
- `/chat` сервиса наставника возвращает `assistantMessageId` —
  привязка оценки к конкретному ответу.
- Версии workspace-пакетов 2.0.0 -> 3.0.0.

## [2.0] - 2026-11-20

Фаза 2 дорожной карты «ИИ-наставник» (недели 15–22): RAG-чат с цитатами,
голосовой интерфейс, индексация документов. Все заглушки STUB(phase-2)
в сервисе наставника заменены рабочим кодом.

### Added
- **Провайдер-agnostic LLM-слой** (`apps/ai-mentor/src/llm.ts`): чат,
  эмбеддинги, озвучивание и распознавание речи через OpenAI-совместимые
  эндпоинты; GigaChat, YandexGPT или любой другой провайдер — только
  переменными `AI_*` в .env, без правок кода. Таймаут 60 с, честная
  деградация, когда провайдер не настроен.
- **RAG-конвейер** (`src/rag.ts`): векторный поиск по pgvector
  (`<=>`, косинусное расстояние) с fallback на JS-близость, если
  расширение не установлено; парсинг ссылок `[N]` из ответа — в цитаты
  попадают только реально использованные фрагменты; история диалога
  (последние 8 сообщений) в контексте; при отсутствии фрагментов —
  честный отказ вместо выдумки.
- **Индексация документов** (`src/indexer.ts`, `src/cli-index.ts`):
  нарезка текста по заголовкам и абзацам (целевой фрагмент ~900 знаков),
  батчевые эмбеддинги, перезапись `document_chunks`; CLI
  `npm run index -w @remotebrief/ai-mentor` и эндпоинт
  `POST /admin/index` для переиндексации из консоли.
- **Персистентность диалогов**: `/chat` создаёт `AIConversation` по
  JWT-сессии сотрудника и сохраняет `AIMessage` с цитатами — полный
  аудит обращений к наставнику (метрика пилота «≥ 3 обращения»).
- **Голосовой интерфейс**: `POST /tts` — mp3-озвучивание страницы или
  ответа (лимит 4000 знаков), `POST /asr` — голосовой вопрос сотрудника
  (webm/mp3 до 10 МБ) -> текст.
- **Интеграция в мобильный поток** (`apps/web`): прокси-маршруты
  `/api/ai/{chat,tts,asr,index}` с проверкой сессий; в читалке и на
  экране курса — раскрывающаяся панель наставника; голосовой вопрос
  через MediaRecorder («Голос» -> запись до 60 с -> распознавание ->
  поле ввода), кнопка «Прослушать ответ» на каждом ответе, диалог
  не теряется между сообщениями.

### Changed
- Версии всех workspace-пакетов 1.0.0 -> 2.0.0.
- `ModuleDTO` получил `documentId` — наставник отвечает в контексте
  конкретного документа модуля чтения.

### Degradation (без настроенного LLM-провайдера)
- Наставник работает: отдаёт релевантные фрагменты документов как
  источники, честно сообщает, что генерация не настроена; голосовые
  функции возвращают понятную ошибку; мобильный поток не ломается.

## [1.0] - 2026-11-20

Фаза 1 дорожной карты «Ядро MVP» (недели 5–14): внутренняя эксплуатация
без ИИ. Все заглушки STUB(phase-1) заменены рабочим кодом.

### Added
- **Назначения** (`Assignment`): очередь инструктажей сотрудника и единица
  отчётности; срок считается от даты назначения (deadlineDays курса);
  массовое назначение из консоли (сотрудники или подразделение целиком).
- **Чтение с постраничным подтверждением**: страницы модуля (`ModulePage`),
  факты подтверждения с временем на странице (`ReadingEvent`), кнопка
  разблокируется по минимальному времени чтения (1 с на 12 слов, не менее 5 с).
- **Движок тестов**: попытки с лимитом (по умолчанию 3), серверная проверка
  ответов, порог 80%, варианты перемешиваются, отметки правильности клиенту
  не передаются; завершение — оценка и запись результата.
- **Движок протоколов**: автонумерация ГГГГ-NNNN, подписи комиссии
  (`ProtocolSignature`) для каждого активного участника с ролью COMMITTEE,
  решение SIGNED/DECLINED (одно на протокол, неизменяемое); все подписали →
  протокол SIGNED, назначение завершено; печатная форма протокола
  (HTML, автопечать) в консоли.
- **Письма**: письмо о протоколе на почту офиса (nodemailer; без SMTP
  письмо пишется в журнал `MailLog` как QUEUED); все письма логируются.
- **API сотрудника** (10 маршрутов): вход по личному коду (bcrypt-хеши,
  JWT-cookie 7 дней), карточка назначений, подтверждение страниц,
  старт/ответ/финиш теста, состояние попытки, карточка протокола.
- **API консоли** (12 маршрутов): вход по email+паролю (роли ADMIN /
  INSTRUCTOR / COMMITTEE), документы с версиями и статусами
  (DRAFT → PUBLISHED → ARCHIVED), конструктор курсов (модули чтения +
  тесты, структурные правки блокируются при наличии назначений),
  назначения, реестр протоколов для комиссии, KPI-отчёты, печатная форма.
- **Мобильный UI**: дашборд «Мои инструктажи» с прогрессом и сроками,
  читалка, полный экран теста с экраном результата, карточка протокола
  со статусом подписания.
- **Консоль UI**: библиотека, конструктор курсов, назначения, комиссия,
  отчёты (KPI против целей пилота: ≥95% в срок, ≤30 мин, подписи).
- **Seed**: демо-организация — 3 документа, курс вводного инструктажа
  (8 страниц, тест из 8 вопросов), 6 сотрудников с кодами 1111–6666,
  3 пользователя консоли, назначения для двух сотрудников.
- **Доменная модель расширена 17 → 21 сущность**: `User`, `Assignment`,
  `ModulePage`, `ReadingEvent`; документ получил текстовое поле `content`
  (источник модулей чтения и RAG-фрагментов).
- Tailwind v4 подключён через `@tailwindcss/postcss`; восстановлены
  утилиты `card`/`btn-primary`/`btn-secondary`; tsconfig-и пакетов.

## [0.2.0] - 2026-11-20

### Changed
- Проект переименован из BriefHub в RemoteBrief: npm-пакеты
  (@remotebrief/*), имя БД и бакета в dev-окружении, документация,
  лицензия.
- Причина: домен briefhub.ru занят сторонним сервисом (B2B-портал для
  веб-студий). Проверка имени RemoteBrief: занято только рассылкой
  remotebrief.com о remote work — другой класс продуктов, конфликта нет.

## [0.1.0] - 2026-11-20

### Added
- Скелет монорепозитория под рабочим названием BriefHub: apps/web
  (Next.js 16), apps/ai-mentor, packages/database (Prisma),
  packages/shared.
- Доменная модель: 17 сущностей (сотрудники, коды доступа, документы,
  фрагменты для RAG, курсы, модули, тесты, попытки, протоколы, подписи,
  почтовый журнал, аудит, диалоги ИИ-наставника).
- Мобильный поток: вход по личному коду, читалка с постраничным
  подтверждением, тест, экран протокола.
- Консоль администратора: библиотека документов, курсы, комиссия, отчёты.
- Сервис ИИ-наставника: RAG с обязательными цитатами, промпт с защитой
  от галлюцинаций, эндпоинты TTS/ASR (заглушки интеграции).
- Инфраструктура разработки: docker-compose (Postgres, MinIO, MailHog),
  .env.example, CI-конвейер.
- Документация: концепция продукта, архитектура, дорожная карта,
  юридический контур, анализ конкурентов, черновик OpenAPI.
