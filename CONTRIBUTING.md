# Contributing to RemoteBrief

## Как вносить изменения

1. Создайте ветку от `main`: `git checkout -b feat/<краткое-имя>`
2. Внесите изменения, соблюдайте стиль TypeScript (ESLint/Prettier).
3. Убедитесь, что проходят проверки: `npm run lint && npm run typecheck`.
4. Оформите коммит по Conventional Commits:

   - `feat:` новая функциональность
   - `fix:` исправление ошибки
   - `docs:` документация
   - `chore:` инфраструктура и обслуживание
   - `refactor:` рефакторинг без изменения поведения
   - `test:` тесты

   Пример: `feat(web): постраничное подтверждение ознакомления`

5. Откройте Merge Request в GitVerse; ревью обязательны для `main`.

## Правила предметной области

- Любая логика нормативного характера (сроки, пороги, формы протоколов)
  должна ссылаться на НПА в комментарии и проверяться аналитиком службы ОТ.
- ИИ-наставник: изменения промпта согласуются с владельцем продукта;
  каждый ответ обязан содержать цитаты-источники.
- Персональные данные: новые поля ПДн согласуются с юриспектом (152-ФЗ),
  хранение — только в РФ.
