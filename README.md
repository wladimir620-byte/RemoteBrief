# RemoteBrief

**Дистанционные инструктажи для мобильных сотрудников — с ИИ-наставником и автопротоколами.**

RemoteBrief — веб-платформа, которая заменяет бумажные журналы инструктажей:
организация загружает нормативные документы (приказы, программы, технологические
карты, федеральные законы), новый сотрудник получает ссылку и личный код, проходит
инструктаж с телефона, сдаёт тест, а система автоматически формирует протокол
и отправляет его на почту офиса для подписи комиссией.

## Статус проекта: v3.0 — фаза 3 «Пилот»: инструменты готовы

Работает полный контур: документы → назначение → чтение
с постраничным подтверждением → тест (порог 80%) → протокол →
письмо комиссии → подписание → архив — плюс ИИ-наставник:
RAG-чат со ссылками на пункты документов, озвучивание (TTS)
и голосовые вопросы (ASR).

Для пилота добавлены: сбор жалоб на наставника («Ответ неточен»),
KPI-отчёты против целей дорожной карты с разрезом по подразделениям
и экспортом CSV, памятка для обучения комиссии (docs/pilot-guide.md).

## Ключевые возможности

- **Библиотека нормативных документов** — приказы, программы инструктажей,
  технологические карты, НПА; версии, теги аудиторий, публикация сотрудникам.
- **Мобильный вход без пароля** — ссылка из SMS/мессенджера/QR + 4-значный
  личный код. Компьютер и приложение не нужны.
- **Чтение с подтверждением** — сотрудник постранично подтверждает
  ознакомление; каждая отметка и время на странице фиксируются в журнале аудита.
- **Тестирование** — вопросы по программе, порог прохождения (по умолчанию 80%),
  ограничение попыток (по умолчанию 3), серверная проверка ответов.
- **Автопротокол** — при успешном прохождении формируется протокол,
  уходит на почту офиса, комиссия подписывает в реестре, документ уходит в архив.
- **Консоль администратора** — библиотека, конструктор курсов и тестов,
  назначения, реестр протоколов, отчёты по KPI пилота.
- **ИИ-наставник** — объясняет документы текстом и голосом (TTS),
  принимает голосовые вопросы (ASR); каждый ответ опирается на
  RAG-фрагменты документов и содержит ссылки на источники. Диалоги
  сохраняются для аудита; без настроенного LLM-провайдера наставник
  работает в режиме деградации (показывает источники без генерации).
- **Инструменты пилота (фаза 3)** — оценки ответов наставника с жалобами
  на неточность, KPI-отчёты против целей (в срок ≥95%, ≤30 мин, подписи
  за 1 день ≥90%, обращения ≥3, жалобы ≤5%) с экспортом CSV,
  памятка обучения комиссии.

## Архитектура (кратко)

```
Сотрудник (телефон, PWA)
   │
apps/web — Next.js 16 (App Router, TypeScript, Tailwind)
   ├── мобильный поток: /login → /course → /quiz → /protocol
   ├── консоль админа: /library /courses /committee /reports
   └── Prisma
         │
PostgreSQL (21 сущность, pgvector) + S3/RustFS (файлы, PDF, фаза 4)
         │
apps/ai-mentor — Express-сервис: /chat (RAG + цитаты), /tts, /asr
         │
LLM-провайдер (GigaChat / YandexGPT / OpenAI-compatible, через env)
         │
SMTP → протокол на почту офиса → подпись комиссии → архив
```

Подробно: [docs/architecture.md](docs/architecture.md).

## Быстрый старт

Требуется Node.js 20+.

```bash
# 1. Инфраструктура для разработки (Postgres, RustFS, MailHog)
docker compose up -d

# 2. Зависимости
npm install

# 3. Конфигурация: .env + копии для Prisma и Next.js (автоматически)
npm run env:setup        # создаст .env из .env.example и разложит по пакетам

# 4. Prisma-клиент. На npm 11.20+ postinstall-скрипты блокируются
#    (предупреждение "install scripts not yet covered by allowScripts"),
#    поэтому генерируем клиента явно:
npm run db:generate

# 5. Схема БД и демо-данные (db:push/db:seed сами обновляют копии .env)
npm run db:push
npm run db:seed

# 6. Запуск
npm run dev      # web: :3000, ai-mentor: :8001

# 7. (после подключения LLM-провайдера) индексация документов для RAG
npm run index -w @remotebrief/ai-mentor
```

### Демо-доступы (после db:seed)

| Роль | Куда | Доступ |
|---|---|---|
| Служба охраны труда | `/admin/login` | `ot@remotebrief.ru` / `demo1234` |
| Председатель комиссии | `/admin/login` | `predsedatel@remotebrief.ru` / `demo1234` |
| Член комиссии | `/admin/login` | `chlen@remotebrief.ru` / `demo1234` |
| Сотрудник (назначен курс) | `/login` | код `1111` (Иванов) или `2222` (Петрова) |
| Сотрудник (без назначений) | `/login` | коды `3333`–`6666` |

Тестовый сценарий фазы 1:

1. С телефона откройте `http://localhost:3000/login` и введите код `1111`.
2. Пройдите курс: подтвердите все 8 страниц чтения (кнопка разблокируется
   по времени чтения).
3. Сдайте тест: минимум 80% (8 вопросов, до 3 попыток).
4. Протокол создастся автоматически, письмо появится в MailHog
   (`http://localhost:8025`); статус — в карточке протокола сотрудника.
5. В консоли (`/admin/login`, predsedatel@remotebrief.ru) в разделе
   «Комиссия» подпишите протокол — когда подпишут все члены комиссии,
   назначение сотрудника перейдёт в «Завершён».
6. Отчёты: `/reports` — KPI против целей пилота.

Проверка фазы 2 (ИИ-наставник):

1. В читалке курса раскройте «Не понятно? Спросите наставника»
   — наставник отвечает в контексте открытого документа.
2. Без LLM-провайдера (`AI_API_KEY=change-me`) наставник работает
   в режиме деградации: показывает найденные фрагменты-источники
   и честно сообщает, что генерация не настроена.
3. Заполните `AI_BASE_URL`/`AI_API_KEY`/`AI_MODEL`/`EMBEDDING_MODEL`
   в `.env`, запустите `npm run index -w @remotebrief/ai-mentor` —
   наставник начнёт отвечать с ссылками `[N]` на пункты документов.
4. Голос: кнопка «Голос» — вопрос с микрофона (ASR),
   «Прослушать ответ» — озвучивание (TTS). Диалог сохраняется
   между сообщениями (AIConversation/AIMessage).

Проверка фазы 3 (пилот):

1. В чате наставника под каждым ответом — «Полезно» / «Ответ неточен»;
   отметка сохраняется в диалоге и попадает в метрику жалоб.
2. Отчёты `/reports` — пять KPI пилота против целей с разрезом
   по подразделениям; кнопка «Экспорт CSV» выгружает сводку для Excel.
3. Обучение комиссии — docs/pilot-guide.md (вход, подписания, жалобы,
   типичные ситуации).

| 0. Подготовка | 1–4 | ТЗ, юридический аудит, дизайн-система | Готова |

«Новый репозиторий»), затем:

```bash
cd RemoteBrief

git push -u origin main
```

GitVerse также поддерживает импорт/зеркалирование репозиториев из GitHub
в один клик (см. https://gitverse.ru/docs/collaborative/repositories/faq).
